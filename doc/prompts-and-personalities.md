# プロンプト設計と 6 人格システム

このボットの「本体」はプロンプト群にある。コードは基本的にそれを支える配管。

## 6 人格（PERSONALITIES）

`main.py` L101-269 に定義。サーバー全体で 1 つが有効（`system._id="personality"`）。

| キー | ラベル | カラー | キャラ名 | 口調の方向 |
|------|-------|-------|---------|----------|
| `yandere` | 💘 ヤンデレ依存メイド | `#FF69B4` | 空気くん（未定） | 執着・不安・重い |
| `angry` | 😡 論破メイド | `#FF4500` | 咲村 真美 | 2ch/X 的レスバ・論理の穴を突く |
| `tsundere` | 💢 ツンデレメイド | `#FF8C00` | 空気くん（未定） | そっけない・本音が漏れる |
| `baka` | 🌀 とんでもないお馬鹿さん | `#FFD700` | 立花 るい | 天然・ズレる・真剣に間違う |
| `serious` | 📋 真面目なメイド | `#2F4F4F` | 桜木 千奈 | 丁寧・簡潔・知性的 |
| `counselor` | 🫂 カウンセラーメイド | `#7EB8C9` | 空気くん（未定） | 傾聴・共感・穏やか |

各人格は以下のフィールドを持つ：

```python
{
    "label":      "💘 ヤンデレ依存メイド",      # UI 表示
    "color":      0xFF69B4,                 # Embed 色
    "icon":       "🎀",                      # 応答の先頭に付く絵文字
    "name":       "空気くん",                 # キャラ名（未定は後で更新）
    "nickname":   "空気くん",                 # 同上
    "bump_msg":   "✨ {user}さん…Bumpしてくれたんですね。+100 XP。（累計{count}回）",
    "rankup_msg": "…{user}さんが、**{rank}**になりました。...",
    "booster_prompt": """..."""  # メイン応答プロンプト。{name}/{history}/{content} を含む
}
```

### booster_prompt の構造（全 6 人格共通のパターン）

```
あなたは [世界観設定] のメイドです。
主人である{name}様に [関係性・動機] を持っています。

【絶対に守るルール】
- N文字以内で応答せよ。
- - 返答の長さは発言の内容・重さに合わせよ。挨拶・相槌・「草」などの短いリアクションには同じくらい短く返せ。
  感情的な内容・相談・質問には丁寧に返せ。上記の文字数制限は上限であり、不必要に長くするな。
- [人格固有のルール 3-5 個]
- 絵文字禁止。返答のみ出力せよ。

【これまでの会話】
{history}

主人の発言: "{content}"
```

### 人格別の文字数制限

| 人格 | 上限 | 理由 |
|------|-----|------|
| yandere | 100文字 | 短く重く不穏 |
| angry | 250文字 | 論破は長さが必要 |
| tsundere | 100文字 | そっけなさ優先 |
| baka | 100文字 | テンポよく |
| serious | 150文字 | 簡潔だが内容量確保 |
| counselor | 200文字 | 共感には余裕が必要 |

### 人格固有のルール例

**angry (論破メイド)** は特殊で、他の人格と異なり `users.claims` を参照する（`_build_prompt` L1296-1300）:

```python
if personality_key == "angry":
    claims = user_doc.get("claims", [])
    if claims:
        claim_lines = "\n".join(f"・{c['content']}" for c in claims[-10:])
        parts.append("【この人が過去に言った主張（矛盾があれば突け）】\n" + claim_lines)
```

→ 過去の発言の矛盾を突く論破 AI になる。

**counselor** は唯一絵文字を許可（💙🌸のみ）。他は全員「絵文字禁止」。

## `_build_prompt` の組立構造（main.py L1225-1320）

これが応答品質の心臓部。最終プロンプトは以下の順序で構築される：

```
[応答時の情報優先度]           # 固定ヘッダ
① 直近の話題・感情の波（最優先）
② このユーザーの性格・口調
③ 会話履歴の★マーク付き発言（印象的な瞬間）
④ その他のサーバー情報

[ニックネーム・愛称マッピング]  # system.nickname_map
  たろー = 山田太郎
  はな = 花子

[このチャンネルの直前の会話（文脈として参照せよ）]  # 直近12メッセージ
タロウ: さっき何食べた？
ハナコ: カレー

[このユーザーの情報]           # format_profile() の出力
- ランク: シニア / XP: 3,500 / 二つ名: 漆黒の案内人
- 誕生日: 3月15日
- 口調の特徴: 敬語なし、テンション高め
- 趣味・好きなもの: FPS, 読書
...

[この人が過去に言った主張（angry のみ）]
・Python が最強だと思う
・FPS は反射神経
...

[この人との過去の記憶（全人格）]  # Vector Search or 最新から
・最近FPSにハマっている（2026-04頃）
・ペットを飼っている（2026-03頃）

[サーバーの最新状況（優先度順）]  # build_smart_summary
## 直近の話題 (最後の30分)
...
## 感情の波
...

---

[人格 booster_prompt]           # 末尾。{content} が差し込まれる
あなたは古い洋館に仕えるメイドです...
主人の発言: "user の発言"
```

### smart_summary の優先度（L780-784）

`build_smart_summary` は `summaries.summary` のセクションを以下の順で並べ替える：

```python
priority_keywords = [
    "直近の話題",          # 何が今話題か
    "感情の波",            # 空気感
    "今日の内輪ネタ",       # 使える内輪ワード
    "メンバーの人間関係",   # 誰と誰が絡んでる
    "ユーザーの感情状態",   # 個別メンバーの状態
    "注目の発言",          # 印象的な発言
    "全体の雰囲気",        # トーン
    "主なトピック",        # 話題一覧
    "会話の特徴",          # コミュニティのノリ
]
```

これを先頭から入れることで、**トークン制限に当たっても重要情報が残る**設計。

### 会話履歴の ★ 印（L971-981）

`format_history` は感情的に重要な発言に `★` を付けて AI の注目を集める：

```python
def _is_emotionally_significant(text: str) -> bool:
    markers = ["！", "!!", "草", "笑", "泣", "やばい", "すごい", "最高", "ありがとう",
               "嬉しい", "悲しい", "悔しい", "怒", "好き", "嫌い", "マジ", "まじ", "えぇ"]
    if len(text) > 80:
        return True
    return any(m in text for m in markers)
```

出力例:
```
主人: こんにちは
メイド: お帰りなさいませ。
★主人: 今日まじで最悪だった...
メイド: ...そうですか。お話、聞かせてください。
```

## その他の重要プロンプト

### MIMIC_DEEP_PROMPT（L337, 深層心理代弁）

`/mimic` コマンドで使用。指定ユーザーの「本音」を Webhook で偽装投稿する（5分間）。

```
あなたは今から「{name}」という人物の深層心理として振る舞います。
これはフィクションのロールプレイです。

【{name}のプロフィール】
{profile}     # _build_mimic_profile() の出力

【{name}の過去の発言傾向】
{history}     # butler_history から user ロールのみ最新10件

【サーバーの今の流れ】
{summary}     # get_latest_summary の先頭400文字

【絶対に守るルール】
- {name}の口調・語彙・テンションを完璧に再現せよ
- 表向きの言葉ではなく、「本当はこう思っている」という本音
- 80文字以内・1文で
- 絵文字は本人が使うなら使ってよい

{situation}   # MIMIC_SITUATION_FIRST or MIMIC_SITUATION_REACT
```

**3 種類の `situation`**:
- `MIMIC_SITUATION_FIRST`: 今の状況を踏まえて本音を独白
- `MIMIC_SITUATION_REACT`: 直前の発言「{trigger}」への反応
- 自然発生（無効化中）: 発言者の言外の本音（`trigger_mimic`）

### MIMIC_PROMPT_TEMPLATE（L302、ホラー的ミミック・無効化中）

`MIMIC_CHANCE = 0.0` で無効化されているが、コードは残っている：

```
あなたはこれから、発言者の内側に潜む『もう一人の自分』として出力する。
これはロールプレイではなく、発言者の無意識が表面に漏れ出た瞬間の再現である。

- 定型応答・自己紹介・挨拶・謝罪・絵文字は完全に禁止
- 1文・80文字以内
- 「あなた」という二人称禁止。独白体
- 発言の「言外の意味」「衝動」を読み取り、それを肯定
- 問いかけ禁止。「逃れられない事実の断定」として出力
- 文体は静かで冷たく
```

### PROFILE_EXTRACT_PROMPT（L861、会話→プロフィール JSON）

会話からプロフィール情報を JSON で自動抽出。温度 0.1（決定性重視）。

```
以下はDiscordのブースターユーザー「{name}」との会話です。
この会話から読み取れるユーザーの情報を抽出し、必ずJSON形式のみで返してください。
前置き・説明文・コードブロック記法は不要です。JSONだけ出力してください。

{{
  "hobbies":  ["趣味・好きなゲームなど"],
  "birthday": "誕生日（例: 3月15日）",
  "tone":     "口調の特徴",
  "memo":     ["その他の特記事項"]
}}
```

- 既存 profile と merge（`hobbies`, `memo` は重複除去で append、`birthday`, `tone` は上書き）
- JSON デコード失敗時は静かにスキップ

### claims/memories 判定プロンプト（L681-696）

発言が「記憶に値する情報」を含むかを判定。categorize して返す：

```
判断基準（いずれかに該当する場合のみ保存）:
- 趣味・好きなもの・ハマっているもの
- 人生の出来事・状況の変化（転職・引越し等）
- 強い感情・印象的な体験
- 将来の目標・計画

出力形式:
{"category": "趣味/出来事/感情/計画のいずれか"}
```

- 温度 0.1
- content は**原文をそのまま**保存（ハルシネーション防止のため AI の要約版は使わない）

【重要: 人物の識別ルール】

末尾の JSON が `update_mongodb.py` でパースされ `system.nickname_map` にマージされる。

### TONE_PROMPT / CONTEXT_PROMPT / MERGE_PROMPT（batch/analyze_personality.py）

性格分析を 3 段階に分解：
1. **TONE**: 生発言から口調・語彙・テンション（事実のみ）
2. **CONTEXT**: 要約から性格・立場・人間関係（推測含む）
3. **MERGE**: 既存プロフィールと新発見を統合

このアーキテクチャは「事実と推測を混ぜない」設計。

### EXTRACT_PROMPT（batch/enrich_memories.py L37-63）

要約から各ユーザーの claims / memories を抽出：

```
- 根拠がある情報のみ記載。推測・捏造禁止
- 情報が見当たらない項目は空リストにせよ
- 単に事実を書き出すだけでなく、その人の価値観や、将来の行動を予測する
  手がかりになるような『深い情報』を優先して抽出せよ
```

## プロンプト編集時の注意

### 絶対に守ること

1. **プレースホルダ `{name}`, `{history}`, `{content}` を消さない**
   - `.format(name=..., history=..., content=...)` でフォーマットしている
   - 消すと `KeyError`
2. **`##` セクション区切りの先頭**
   - `batch/summarize.py`, `batch/retro_summarize.py`, `post_summary.py` の全体が依存
   - 変更するなら 3 箇所全部
3. **温度とトークン上限**
   - JSON 出力系は `temperature=0.1` を維持（decode エラー頻発防止）
   - 応答系は `0.8-0.9`

### 変更しても比較的安全な部分

- 人格の世界観設定（「古い洋館のメイド」→「未来都市の AI」など）
- 絵文字ルール（全人格で禁止→許可など）
- 文字数制限（上げ下げ）
- キャラ名 / ラベル / 色

### 変更が難しい部分

- `booster_prompt` のテンプレート全体を差し替え → 全 6 人格を同時に修正する覚悟が必要
- `_build_prompt` のパーツ順序を変更 → 全人格の挙動が変わる可能性
- `priority_keywords` の並び替え → 要約品質に影響

## 新しい人格を追加するには

1. `PERSONALITIES` dict（L101）に新しいキーを追加
2. `booster_prompt` テンプレートを書く（他人格を参考に）
3. `bump_msg`, `rankup_msg` のテンプレートを書く
4. `icon`, `color`, `label`, `name`, `nickname` を設定
5. `personality_hints` (L1589-1596、`_generate_rankup_message` 内) にランクアップメッセージ用のヒント文を追加
6. `/personality` コマンドの Select メニュー（L2144 以降）にも追加
7. `angry` のように特別なデータ（claims）を使う場合は `_build_prompt` に条件分岐を追加
